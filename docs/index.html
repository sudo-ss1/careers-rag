Retrieval

Hybrid beats lexical by 15% and dense by 124%

Reciprocal Rank Fusion combines the two ranked lists by rank rather than score — BM25 scores are unbounded and corpus-dependent, cosine lives in [−1, 1], and adding them needs a normalisation that shifts every time the corpus does.

MetricBM25DenseHybrid

The one place hybrid loses is MRR — 0.779 against BM25's 0.797 — because fusion demotes the rank-1 hits BM25 gets on ID lookups. An honest trade: a little top-1 precision on exact lookups for far better recall everywhere else.

What evaluation caught that a demo would not

Three bugs found by measuring

A grounding check stricter than the model's formatting fails closed on correct answers

Citations were extracted with \[(\d{6,8})\]. The model answered “requisition 1440127 is for…” in prose, the regex matched nothing, and a correct answer was discarded as ungrounded — while retrieval had it at rank 1 the whole time. Verification has to be independent of formatting.

Raw BM25 scores cannot be thresholded across queries

Calibrating an abstention gate on BM25 failed outright: out-of-corpus queries scored higher (max 14.4) than the answerable mean (11.6), because BM25 scales with query length and term rarity. Cosine similarity is bounded and comparable. BM25 is not.

The statistically optimal threshold was the wrong design

Youden's J picked 0.41 — the best a single threshold can do — and it false-abstained on 15% of answerable queries, every one an exact-token lookup where dense is the weak arm. The distributions genuinely overlap (answerable min 0.364 below out-of-corpus max 0.465), so no threshold separates them. Retuning the first gate for sensitivity and letting the grounding check supply specificity cut false abstention to 3% — with refusal accuracy and hallucination count unchanged.

Method

How it fits together

Chunking follows the document, not a character count

Postings split on their own section headings — Meet the Team, Minimum Qualifications — and every chunk carries a contextual header with title, requisition ID, category and location before it is embedded. A bare qualifications list is unretrievable on its own, because nothing in it says which job it belongs to.

Ground truth is tracked per document, never per chunk

Changing the chunking strategy is the experiment that gets run most often. Chunk-level labels would be invalidated by every one of those runs.

Abstention is two independent layers

A permissive similarity gate — cheap, deterministic, immune to persuasive generation — then the model's own NO_MATCH plus a citation check that drops any requisition ID absent from the retrieved context. An answer left with no verified citation becomes a refusal.

Limitations

What these numbers don't tell you

  • Label bias. Golden labels derive from ML-extracted skill tags, which come from the description text — so a labelled term usually appears verbatim in the document. That flatters lexical retrieval. Paraphrase queries avoiding corpus vocabulary would counterbalance it, and aren't built yet.
  • 40 queries is small. Enough to separate three strategies by a wide margin; not enough to resolve small differences.
  • Exact search, not approximate. At ~7k chunks a brute-force scan is sub-millisecond, so these measure retrieval quality without ANN recall loss. At production scale this is where HNSW goes — and where you'd compare ANN recall against these exact results to size ef_search.
  • 131 of 1,277 listed postings returned no description — expired or rate-limited — and are excluded from the corpus.
